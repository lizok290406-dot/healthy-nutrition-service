# Техническое задание: NutriTrack

## 1. Название и концепция
**NutriTrack** — сервис подбора здорового питания для студентов с ограниченным бюджетом.

Проблема: студенту сложно питаться сбалансированно и при этом укладываться в небольшой бюджет. Сервис помогает подобрать продукты с лучшим соотношением «польза/цена», считает КБЖУ и стоимость дневного рациона и показывает, насколько питание соответствует индивидуальной норме.

## 2. Роли пользователей
| Роль | Возможности |
|------|-------------|
| Гость | Каталог продуктов, страница «Подбор», поиск через внешний API, главная |
| Авторизованный пользователь | Дневник питания, расчёт нормы калорий и БЖУ, соответствие нормам, учёт бюджета, профиль |
| Администратор | Управление всеми данными через Django Admin |

## 3. Модели данных (сущности)
**Category (Категория)** — `name`, `emoji`, `description`.

**Product (Продукт)** — `name`, `category` (ForeignKey → Category), `calories`, `protein`, `carbs`, `fat`, `emoji`, `price_per_100g`. Значения КБЖУ и цена — на 100 г.

**UserProfile (Профиль)** — `user` (OneToOneField → User), `age`, `weight`, `height`, `gender`, `activity_level`, `goal`, `daily_calorie_goal`.
Методы: `calculate_bmr()`, `calculate_tdee()`, `calculate_macros()`, `calculate_bmi()`, `get_bmi_category()`.

**DiaryEntry (Запись дневника)** — `user` (ForeignKey → User), `product` (ForeignKey → Product), `date`, `meal_type`, `amount_grams`.
Свойства: `calories_consumed`, `protein_consumed`, `carbs_consumed`, `fat_consumed`, `cost`.

**BudgetPlan (Бюджет питания)** — `user` (ForeignKey → User), `date`, `daily_budget`.
Методы: `get_spent()`, `get_remaining()`, `is_within_budget()`, `get_percent_spent()`.

Связи: Category → Product → DiaryEntry образуют связанную цепочку; DiaryEntry и BudgetPlan привязаны к пользователю; UserProfile расширяет стандартную модель User.

## 4. Основные сценарии (User Stories)
1. Гость открывает «Подбор продуктов», задаёт максимальную цену и калорийность — получает список самых выгодных продуктов, отсортированных по соотношению «польза/цена» (расчёт средствами БД через F-объекты).
2. Пользователь заполняет профиль (вес, рост, возраст, пол, активность, цель) — система рассчитывает суточную норму калорий по формуле Миффлина — Сан Жеора и норму БЖУ.
3. Пользователь добавляет продукты в дневник с граммовкой — система автоматически считает КБЖУ и стоимость порции.
4. В «Дневнике» пользователь видит, насколько съеденное за день соответствует его норме по калориям и БЖУ (в процентах).
5. Пользователь задаёт дневной бюджет на еду и контролирует, укладывается ли в него.

## 5. Технический стек и интеграции
| Компонент | Технология |
|-----------|-----------|
| Backend | Python 3.13, Django 6.0 |
| ORM | ForeignKey, OneToOne, фильтрация, сортировка, агрегации (Count, Avg), F-объекты |
| Внешний API | Open Food Facts (через requests) — поиск продуктов |
| Визуализация | Plotly (интерактивные графики калорий и БЖУ) |
| Frontend | Bootstrap 5.3, Bootstrap Icons, django-crispy-forms |
| Формы | Django Forms / ModelForms с валидацией на сервере |
| База данных | SQLite |
| Хостинг | PythonAnywhere |

## 6. Изменения в ходе реализации
- Внешний API: вместо Nutritionix используется бесплатный Open Food Facts (без ключа).
- Добавлена модель BudgetPlan и учёт стоимости рациона.
- Добавлена страница «Подбор продуктов» с ранжированием через F-объекты.
- Анализ соответствия нормам показывается прямо в «Дневнике» (калории + БЖУ).
- Отслеживание веса упрощено до текущего веса в профиле.
